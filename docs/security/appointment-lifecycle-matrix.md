# Appointment Lifecycle Matrix

Generated by `apps/api/src/patient-portal/appointment-lifecycle-matrix.spec.ts`. Edit the table in
`apps/api/src/testing/appointment-lifecycle.ts`, not this file.

Every permission below is evaluated against the roles a user holds **at the clinic the
appointment belongs to**. A role held at another clinic never applies here, and a role held at
another organization never applies at all.

## Appointment transitions

An appointment row is created already `CONFIRMED` when staff confirm a request, so `CONFIRMED`
is the only state any action can be applied from. The other three are terminal.

| Action | From | To | Requires | Permission | Audit event |
| --- | --- | --- | --- | --- | --- |
| Reschedule | CONFIRMED | CONFIRMED | nothing further | `APPOINTMENT.WRITE` | `APPT.RESCHEDULE` |
| Cancel | CONFIRMED | CANCELLED | a reason | `APPOINTMENT.WRITE` | `APPT.CANCEL` |
| Complete | CONFIRMED | COMPLETED | the start time to have passed | `APPOINTMENT.WRITE` | `APPT.COMPLETE` |
| Mark no-show | CONFIRMED | NO_SHOW | the start time to have passed | `APPOINTMENT.WRITE` | `APPT.NO_SHOW` |

### Every state and action pair

A refusal carries `APPOINTMENT_INVALID_TRANSITION` with the current status, the attempted
action, and the allowed source statuses, and writes nothing.

| Status | Reschedule | Cancel | Complete | Mark no-show |
| --- | --- | --- | --- | --- |
| CONFIRMED | allowed | allowed | allowed | allowed |
| CANCELLED | refused | refused | refused | refused |
| COMPLETED | refused | refused | refused | refused |
| NO_SHOW | refused | refused | refused | refused |

## Request transitions

| Action | From | To | Requires | Permission | Audit event |
| --- | --- | --- | --- | --- | --- |
| Confirm request | REQUESTED, TRIAGED | CONFIRMED | nothing further | `APPOINTMENT.WRITE` | `APPT.REQUEST.CONFIRM`, `APPT.CREATE` |
| Reject request | REQUESTED, TRIAGED | REJECTED | a reason | `APPOINTMENT.WRITE` | `APPT.REQUEST.REJECT` |

No route writes `TRIAGED` or a request status of `CANCELLED`. Both are reachable in the schema
and accepted as a source state, and neither is produced by the system today.

## What a patient can open

| Request | Type | Needs an existing appointment | Requires | Audit event |
| --- | --- | --- | --- | --- |
| Request a new visit | `NEW_APPOINTMENT` | no | nothing further | `APPT.REQUEST.CREATE` |
| Request a cancellation | `CANCEL_APPOINTMENT` | yes | a reason | `APPT.REQUEST.CANCEL_REQUEST.CREATE` |
| Request a reschedule | `RESCHEDULE_APPOINTMENT` | yes | nothing further | `APPT.REQUEST.RESCHEDULE_REQUEST.CREATE` |

A change request never mutates the appointment. It records what the patient asked for and
leaves the decision with staff. The appointment must be `CONFIRMED` and still in the future.

## Reminders

| Action | Queued reminders | Failure reason recorded | New reminder |
| --- | --- | --- | --- |
| Reschedule | suppressed | `APPOINTMENT_RESCHEDULED` | scheduled |
| Cancel | suppressed | `APPOINTMENT_CANCELLED` | none |
| Complete | suppressed | `APPOINTMENT_COMPLETED` | none |
| Mark no-show | suppressed | `APPOINTMENT_NO_SHOW` | none |

Confirming a request schedules the first reminder for 24 hours before the start time, clamped
to now when that moment has already passed. A suppressed reminder is recorded as `FAILED` and
stays visible rather than being deleted. A reminder that escapes suppression is checked again
at send time against the appointment it names, so a stale job still cannot reach a patient.

## Permissions by role

| Permission | SYSTEM_ADMIN | DIRECTOR | MANAGER | DOCTOR | VOLUNTEER | PATIENT |
| --- | --- | --- | --- | --- | --- | --- |
| `APPOINTMENT.READ` | yes | yes | yes | yes | yes | no |
| `APPOINTMENT.WRITE` | yes | no | yes | yes | no | no |
| `PATIENT.PORTAL.READ_SELF` | yes | no | no | no | no | yes |
| `PATIENT.PORTAL.WRITE_SELF_REPORT` | yes | no | no | no | no | yes |

A `SYSTEM_ADMIN` holds every permission through the wildcard grant, and is still admitted to a
clinic only through `ClinicScopeGuard`. A portal patient reaches no staff route at all.
