## Implementation and authority

Confirmed: the approved live artifact's embedded station screen, checked-in R0
pilot, round-3/round-4 decisions, installed Next client-component docs, installed
Sheet/Button/Select implementations and Impeccable adaptation/craft guidance
informed this unit. Shadcn's official component docs were also inspected. No
real-patient or third-party reference directories were read. Browser evidence
uses the isolated synthetic audit database, with both database URLs guarded.

The overview leads with `StationShiftStrip`, a Stations-only presentation around
the existing `useShiftControls` operation. The dashboard, Today and My Assigned
keep their existing presentations. No hook, operation, endpoint, permission
mapping, database, clinical validation or sync implementation was changed.
Off duty, station choices and empty queue/whole-line panels are withheld.
Unknown first reads remain unknown. Failed refreshes disclose the retained data
through the existing additive `useOpsView.refreshError` field.

Shift writes respect `OPS.SHIFT.WRITE`; station choices, claims and screener
controls respect `OPS.STATION.WORK`. Route access still uses `OPS.STATION.READ`.
A page lock waits for start/end reads or pending overlays to reconcile, then
releases so later external changes do not inherit an old success lock. Queued
starts/ends retain existing feedback and recovery badges, with a 44px recovery
floor. Station writes require a confirmed active shift and an online connection.
Pending changes never masquerade as server-confirmed station assignments.

Station choices use the existing Sheet and gestures: bottom below 600px,
right-side from 600px. Open/selection state and the underlying screener draft stay
mounted across width changes. Current station selection still clears it through
the existing API. Refusals leave the Sheet open with the server error and refresh
the line. Success closes it; if reconciliation disables the trigger, focus goes
to the main workspace. Otherwise dismissal restores the trigger.

The oldest queued visit becomes a bounded ticket with a deep-teal, dashed stub,
real patient code, exact wait/check-in time, previous station, actual performer
and handoff note, including returned-to-queue reasons. No sex, age, completed-step
badge or Open chart action was invented from pilot content. Other queue patients
keep their claim/Continue actions, actual holder/screener and handoff details.
Patients already with this account keep Continue access regardless of shift state.
Capacity/places in use remain visible and informational, matching the API.
Station and claim writes have synchronous duplicate guards; successful claims
remain busy through client navigation. Refusals refresh the existing line.

The phone's fixed action uses the short visible label **Take patient**, with the
full patient name in its accessible name. It clears BottomNav, safe area and chat;
long names cannot make the action fill the viewport at 200% root text. The desktop
action remains on the ticket. The screener checkbox's associated label has a
44px hit-area floor on its two actual consumers, overview and station visit.
The whole line uses an actual route stop per active station, gold for the current
station, real counts and real staff/screener names. It switches from vertical to
horizontal at 48rem of available section width, without remounting state. All new
route headings explicitly use IBM Plex Sans. Both theme palettes are semantic.
No new decorative motion was added; existing reduced-motion behavior remains.
