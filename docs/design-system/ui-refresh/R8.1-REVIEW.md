# R8.1: Full route audit

Phase W is complete. This unit expands the permanent six-role plan beyond sidebar routes:
clinic-scoped and legacy aliases, patient edit/consent, encounter routes and tabs, the registration
wizard, station visits, screening events, research exports, account/settings, public/legal/auth
entry/error routes, Keycloak and generated resources. The plan records what each role actually
sees, including redirects and patient-tab fallbacks, rather than assuming every requested view is
allowed. The build manifest is the inventory authority; missing navigable coverage now fails a full run.
Sidebar and account-menu links supplement the explicit plan. The internal `/_global-error`
entry is separately identified as an unverified root state, not represented as a visited URL.

`create-fixture-manifest.cjs` reads synthetic ids only and refuses either database URL outside
`nkwapa_audit`. No new endpoint or application permission is introduced. The wizard's entry POST
is intercepted to reuse the existing seeded encounter, so the route walk creates no clinical
drafts. Normal reads and role guards remain live. Both themes are captured separately at 1440
and 390; Keycloak intentionally retains its light theme under both preferences; earlier filenames could overwrite a theme. The registry fallback chooses a visible link.
The audit now fails on findings instead of merely writing them to JSON.

## Confirmed defects fixed

- Holding bootstrap rendered the real `PageSkeleton` with **zero h1**; axe reported
  `page-has-heading-one`. Its title is now a semantic h1 with the existing record-title type role.
- A synthetic `USER_DISABLED` response rendered `FullscreenStatus` outside the workspace shell
  with no main landmark. Axe reported `landmark-one-main` and `region`. The whole-page status
  now owns a focusable main target. No account was actually disabled.
- The workspace render boundary had a paragraph title and no h1. It now opts into a semantic
  h1 without changing inline error headings elsewhere.
- Patient `/account` and `/settings` had two h1s. Their portal context is now a paragraph while
  their own page title remains the h1. Other portal routes retain their context heading.
- Allergy summaries preceded the first section heading with an h3 on Medications and Medical
  history. Those two placements now use h2; nested prescribing placements retain h3.
- Clinic facts placed Edit buttons beside dt/dd in the description list. Actions now sit inside
  dd, preserving the ruled layout and valid list structure.
- Two alias scans sampled an empty document title while navigating, and the first landing scan
  sampled entrance motion. Public scans now wait for fonts and reveal the full landing document
  before scanning, following the existing landing spec. The harness waits for destination metadata after content and sync settle (an earlier wait
  before the client redirect was insufficient), and consistently requests reduced motion.
  No axe rules are disabled.

The permanent state spec also injects a synthetic render failure and checks that the exception
is not exposed and Try again recovers. Its document request passes through; only the API read is
replaced. The first baseline attempt incorrectly matched the document too and served JSON as a
page; that capture helper was corrected, not product behavior.

## Limits carried forward

- This is a route and state audit, not clinical-save validation or a physical-device study.
  Conditional care-plan/finalization states depend on the encounter workflow; requesting a tab on
  a draft does not prove its finalization form was shown. The record-tab fallback is recorded.
- Public claim/name/invitation routes include their current redirect/error state. Valid one-off
  invitation/claim lifecycles require dedicated fixtures; the earlier staff-invite flow was tested
  in unit 3, but it is not represented as every possible auth state here.
- A root-layout failure that invokes `global-error.tsx` was not injected. Its font/token fallback
  without the root layout remains the R7.5 open item. A root fault requires a separate fault-injection
  build; the ordinary render boundary is exercised without shipping a root fault hook.
- Real devices, screen readers, virtual keyboard, WebKit with local HTTP Keycloak and field
  performance remain unverified. No performance, sync, clinical validation or permission rule
  changed. The older `patient-chart` date expectation already reads `1 Oct` on this branch.
