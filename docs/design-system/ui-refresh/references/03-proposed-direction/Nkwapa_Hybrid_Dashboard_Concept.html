What to preserve when implementing this concept

This is a visual proposal, not a runnable Nkwapa product. All content is synthetic and deliberately depicts the same off-duty Volunteer state visible in the supplied screenshots. Real actions must be wired through existing permissions, workflows, and synchronization semantics.

Phone — welcoming, shift-first

  • Compact clinic and sync header; clear mobile title and context.
  • Small, original medical illustration slot can later hold a restrained Lottie animation.
  • One dominant primary CTA when off duty; station choice only after starting shift.
  • Clinic totals and next steps grouped below the main task.
  • Persistent, permission-derived bottom navigation and safe-area padding.

Tablet — efficient operations desk

  • Compact labeled rail for the high-priority destinations; no phone UI stretched to full width.
  • Three contextual metrics, a prominent shift CTA, and structured workflow steps.
  • Six station counts and a separate personal-work summary.
  • Two-column adaptive content where space allows; single column on narrower layouts.
  • Contextual sync and role state remain visible without monopolizing the header.

Guardrails and responsive intent

  • Preserve teal/gold brand, existing IBM Plex Sans and Source Serif 4 stack, and accessibility.
  • Use shared API data hooks and business logic for all viewport variants.
  • At 600–839px, adapt spacing and sections; around 840px+, prefer a compact rail where it fits.
  • Never show local save as synchronized until server confirmation.
  • Keep animations subtle, replaceable, and optional under reduced-motion preferences.
