sheet. Frontend only, on `ui-refresh/r1-1-tokens`. No routes, navigation labels,
permissions, feature flags, clinical behavior, APIs, database or sync semantics changed.

## Shared contract

- Under 600px: retain the existing phone navigation sheet until R2.2.
- 600 to 1199px: 76px rail, icons above visible wrapping labels at the pilot's 11.5px type role. Group dividers
  preserve hierarchy; group names remain available to assistive technology.
- From 1200px: 232px expanded by default; 64px icons with shared R1.5 tooltips when
  collapsed. The first hover delay is 300ms; keyboard access and scanning remain instant.
- These widths resolve conflicting R0 prose (248/88px, and a later 76px desktop
  collapse) against the shipped approved pilot and round-3 feedback. They are an
  implementation baseline, not a newly invented owner approval.
- A guarded desktop preference survives forced compact modes. Media queries own
  geometry; a desktop media-query subscription changes nav behavior without
  remounting page content. Client-only shell initialization remains intact.
- Keyboard collapse is instant, including keyboard activation of the header
  button. Pointer collapse uses the existing 200ms drawer curve and reverses from
  the current width. Reduced motion removes movement. Logo crossfade is subordinate.
- One `--card` workspace sheet has an 8px inset from 600px, a quiet border and 12px
  corners. Existing document scrolling, main overflow, skip link, navigation progress,
  pending invite notice and chat remain. Navigation scrolls within sticky `100dvh`
  contents, independently of long route content.
- Staff Message delivery is exposed from 600px, with Clinic settings in the account
  menu. Other Header breakpoints are retained, including the portal's behavior.
- Main's final action clearance is 6rem plus the bottom safe area at all widths.
  This narrowly addresses shell-end overlap with the fixed chat launcher. It does
  not establish that every route action or the Sunday appointment failures are fixed.

## Verification

Exact commands, counts, failures and evidence are recorded in `../PROGRESS.md`.
The production build used the handoff's audit flags and isolated `nkwapa_audit`
database. A sandboxed Turbopack attempt stalled at compilation and was interrupted;
the approved outside-sandbox build passed. No source or flag rebuild was needed
for subsequent spec-only changes.

The main run selected 14 relevant specs, one worker, max three failures, and passed
194 tests including six authentication setups. It includes the permanent
`data-table-surfaces` and `overlay-motion` cases, accessibility, responsive/offline,
flag-aware migration, all five staff nav role sets, shell boundaries and interactions,
role access, workspace smoke, dark mode, console checks, screened registry and staff
invitations. No full e2e suite ran. The station-enabled browser build was used;
independent nav unit checks exercise both station flag modes. No flag-off browser
build ran. Legacy `today-offline` tests assert the flag-off board's workflow and
were not repurposed as station-enabled coverage.

The new consumer spec uses authenticated routes with synthetic intercepted list
responses for deterministic sort/page/filter and request-count checks; it does not
claim those synthetic rows came from database reads. Existing integration specs
and the six-role route harness use the seeded audit database. Screenshot capture
was refined after the first pass to wait for dashboard content and retain readable
viewport frames rather than tall full-page thumbnails. This changes evidence capture
only, not production code.

The visual pass found isolated last letters in long rail labels. A stricter browser
assertion then confirmed that Appointments still exceeded the first spacing
correction: two intermediate runs each had 44 passes and two boundary failures (one per theme).
The final correction keeps the approved 76px width, uses the pilot's 11.5px label
role (in rem for text scaling), and makes 74px available to the labels. No navigation
label was renamed. The earlier consumer supplement was interrupted on an incorrect
`View` locator for cards, whose existing action says `View record`; only the test
locator changed, followed by a clean eight-case rerun and two explicit invitation
sort/page/action checks.

A read-only rendered-font measurement confirmed Appointments is 73.12px wide at
11.5px, while every other complete word fits within 72px. The final rail therefore
uses a 1px gutter (74px available) and inset focus rings. The temporary measurement
spec was removed; the permanent complete-word-width assertion remains.

Final source-state verification passed all 46 focused tests, including six auth
setups and 40 browser checks. The six-role normal route audit passed 12 tests
(six auth setups and six role sweeps), producing 228 route/theme/width rows with
zero errors, serious/critical or other axe violations, and horizontal overflow.
The 179 synthetic PNGs comprise 114 normal route shots, 39 shell/consumer shots
and 26 shared table/component shots. Evidence, JSON summaries and filtered logs
remain local and git-ignored. No push occurred. The P1 open-overlay finding and
all stated verification limits remain open; R2.1 is in review. Next: R2.2.
