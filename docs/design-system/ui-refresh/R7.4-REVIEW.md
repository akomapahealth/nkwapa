# R7.4 review: Responsive edge cases

**Scope:** frontend-only on `ui-refresh/r1-1-tokens`: responsive edge cases across the workspace,
portal and public pages, against MASTER sections 5.4, 6 and 10. Clinical saves, validation rules,
permissions, flags and sync semantics are unchanged. Local commit only; no push. No separate agent
review ran.

Guidance applied: Impeccable (context loader, adapt and polish playbooks, craft floor, detector over
the changed files: no findings, regex pass only), Emil Kowalski's design engineering (transitions
over keyframes for interruptible surfaces; the sheet keeps the dialog's clock instead of gaining a
second one; keyboard opens stay instant), Apple's fluid-interface guidance (spatial consistency: a
sheet leaves the way it came; familiarity: alerts stay centred, forms become sheets; no handle where
there is no drag). Mode: Operate (workspace, portal).

## How the findings were made

Two scratch Playwright probes (deleted). The first walked 24 staff and 6 portal routes at nine sizes
the route audit does not cover: 320×640, 599 and 600, 767 and 768, 1199 and 1200 (×800 or ×900),
640×400 (200% zoom of 1280×800) and 844×390 (landscape phone). It recorded document overflow,
elements past the right edge outside a scroller, and truncated text with no way to read the rest,
and shot 320, 640 and landscape. The second opened Create clinic at six sizes (also after a failed
submit) and walked ten routes at four widths with API responses rewritten in the browser, so every
patient, clinic, user, station and medication name carried a ~60-character suffix. No database rows
changed.

**Baseline result:** 270 rows, **0 overflow, 0 errors** at every size, including 320 and 200% zoom.
The breakpoint pairs (599/600, 767/768, 1199/1200) switch shells cleanly. The real defects were
long dialogs on short screens and names that truncate.

### Which dialogs became sheets

Form variant (multi-field forms): Create and Edit clinic, Add and Edit volunteer, New and Edit
screening day, Add volunteers, appointment lifecycle, Today assign and reassign, Link portal account,
research schedule, station line override, reported medication and pharmacy, merge patient, portal
invitation, Change ID document, medical history record, addendum, the portal's appointment change
request, appointment request confirm and decline, staff invite.

Left as centred alerts: every confirmation (cancel screening day, remove from roster, remove role,
deactivate, cancel invitation, discard offline change, cosign or submit a note, duplicate decision),
single-field prompts (correct name, research reason, data request close), read-only lists (revision
history), cookie settings, the install prompt and the landing dialogs.

### Decisions

- **Sheet, not full screen.** A sheet hugs its content and keeps the page visible above it, so a
  short form does not take the whole screen; a long one grows to 0.75rem below the safe-area top.
- **No drag handle.** A handle promises a drag. The house `Sheet` has one because it has the gesture;
  these sheets close with Cancel, Escape or the scrim, as their dialogs always did.
- **Keyboard inset from `visualViewport`, not `interactive-widget=resizes-content`.** The meta is
  Chromium-only and would also push the bottom nav up above the keyboard. The listener works on iOS
  Safari and Chrome alike; a 120px threshold and an editable-focus check keep pinch zoom and URL bar
  changes from reading as a keyboard; focus is read a frame after `focusout` so moving between fields
  with the keyboard up keeps the inset.

## Checked and left alone

- The landscape phone shell (844×390): rail and compact header, nothing clipped.
- 200% zoom (640×400): every route reflows to one column with no overflow.
- The header clinic switcher truncates at 320; it is a button whose menu shows the full name.
- The floating chat button covers the end of some rows on phones; scroll padding already keeps a
  focused control clear of it (R7.2).

## Ranked findings left open

- **P2.** The keyboard inset is verified only by forced CSS values and unit arithmetic: Playwright
  cannot raise a virtual keyboard. Needs an iPhone and an Android phone on staging.
- **P3.** Between 600 and 639px a form dialog is a centred card whose footer buttons still stack
  (`sm:` is 640). Harmless; not changed to keep `DialogFooter` on one breakpoint system.
- **Pre-existing:** `patient-redesign` 44px tab expectation; `vitals` BMI text.
- **Not checked:** real Safari, screen readers, real devices, foldable hinge segments.
