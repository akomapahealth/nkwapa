# R8.2 device and breakpoint matrix

## Scope and units

Build first, verify later, per owner instruction. No browser, screenshot, theme or breakpoint
checks run during build units. Prior W1 to W4, Polish 2 and R8.1 implementations are retained.

1. Guarded matrix support and six role homes (`ec6d69f3`). Captures and geometry observations
   distinguish pointer emulation, theme, text size and viewport. The dedicated config refuses
   either database outside `nkwapa_audit` and never reuses an unknown running API/web server.
2. Data-entry and portal matrix (`b473d399`). Registration drafts, fresh editable encounter
   Vitals/HTN/DM forms, every interview section and Review, a seeded station visit, self-report
   and appointment drafts. Final actions are scrolled into view and hit-tested.
3. Overlay and keyboard matrix. More, sync and chat directory, modal focus traps/return,
   skip navigation and 200% text traversal. Tap emulation is separate from mouse activation.

All eleven requested widths are represented: 320, 390, 599, 600, 744, 839, 840, 1024, 1199,
1200 and 1440. Both themes and both input conditions run separately. Text checks set the root
font to 200%, not browser zoom. Short-height cases use 744 × 360 and overlays add 568 × 320.
This phase adds verification infrastructure; UI corrections are justified by final-pass findings.

## Fast checks

Unit 1: standalone TypeScript, changed-file ESLint/Prettier, six database-isolation Jest tests
pass with two workers. Initial lint found undeclared browser/Jest globals in new harness files;
explicit declarations/imports fixed these before commit. Unit 2: TypeScript and changed-file
ESLint/Prettier pass; related Jest reports no matching suites, with two workers.
Unit 3: TypeScript and changed-file ESLint/Prettier pass; overlay-related Jest reports no matching
suites, and the guard suite passes again (six tests, two workers). The custom config uses an
absolute test directory so moving the config into `playwright/` does not move spec discovery.

Final build, browser run, visual inspection and any failures are pending. The live checklist is
`R8.2-DEFERRED-CHECKS.md`; unchecked entries are not evidence of a pass.

## Evidence and limits

W4's ten volunteer width/theme captures and six-role home axe checks are prior evidence, as are
R8.1's 390/1440 normal-route observations. They do not prove the new intermediate conditions.
Fresh synthetic records in the audit database are used for editable forms; the station visit
retains whatever state the seed provides. Conditional care-plan and finalization coverage is
not claimed from a draft encounter or a tab fallback.

Still unverified: physical devices, screen readers, safe-area hardware/browser chrome, virtual
keyboards, WebKit authentication over local HTTP Keycloak, valid one-off invitation/claim states,
and root global-error fonts/tokens without RootLayout. A viewport screenshot does not verify
touch gestures, keyboard hardware or performance. No clinical validation, permission, API,
offline or sync semantics are changed. No screening conflict dialog is built: Polish 2 unit 5
explicitly scoped it out because the online and offline writes share the outbox path.

Separate follow-ups stay separate: version checks, Crisis acknowledgement, offline
empty-medication attestation and staging auth memory. No deployment, push or GitHub issue.
