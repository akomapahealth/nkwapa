## Further findings and corrections

- **Confirmed:** staff, doctor, volunteer, manager and director homes had 4px document overflow
  at 320px/200% with touch emulation. Doctor/director also had 28px main overflow in all four
  theme/input contexts; patient home had 4px main overflow in all four. Manager dark/mouse at
  600px had a single 2px main measurement. The causes of the remaining main overflows are
  **unknown**; the 2px sample may be a resize transient and is not called a confirmed persistent
  product defect. All remain on the checklist for diagnosis with settled captures.
- **Confirmed:** chat's whole-page axe scan found an unnamed dashboard Refresh button. Trace
  snapshots show its live region keeps its ancestry exposed while Radix hides its label span.
  `16ba534b` moves the live region beside the button, preserves its announcement, and adds an
  explicit name. The same commit makes More use the other bottom labels' wrapping rule.
  **Strong inference:** More's unwrapped label explains the touch overflow. Neither correction
  has a passing post-fix browser result.
- **Confirmed:** contact-sheet inspection exposed loading placeholders in several early home
  captures. These are not proof of settled role-home layout. `9a9e14a6` now waits for the live
  dashboard response, a role-specific content marker, and absence of busy state. It also polls
  resize overflow for 1.5s instead of treating a two-frame sample as settled.
- **Confirmed:** all four new keyboard cases reached their `:focus` locator failure. The harness
  now uses `:focus-within` for native fields and separately checks actual active-element
  containment in main. Native date segments can focus within a host without matching `:focus`
  (MASTER focus rule); whether this fully explains these failures remains **unverified**.
- **Confirmed:** HTN's first save returned APPLIED. The correction included `baseUpdatedAt` and
  returned ERROR / VALIDATION_ERROR, `property baseUpdatedAt should not exist`. I had not rebuilt
  the API before the run. Its compiled service lacked the committed `takeBaseUpdatedAt` helper;
  the source already strips this field before strict DTO validation. The existing API was rebuilt
  successfully after the invocation, and the compiled service now imports/calls the helper.
  No API source or save semantics were changed. **Unit 5 compatibility is still unverified:**
  HTN, DM and vitals must be rerun with that fresh API, even though DM/vitals passed here.
