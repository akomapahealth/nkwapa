# R3.8 review: Encounters, plus pointer-aware controls

**Scope:** Frontend-only encounter workspace and new-visit wizard on
`ui-refresh/r1-1-tokens`, plus an owner-directed cross-cutting change to control
size, radius and action placement. Local commit only; no push. The owner's
`HANDOFF-R3.1.md` modification stays separate. No separate agent review ran.

## Owner decisions (2026-11-10)

The owner reported that buttons looked squircle, that buttons and fields felt
slightly large on every device, and asked for desktop actions on the right.
Four options were put to the owner, who chose:

- **Pointer-aware sizing.** Tokens in `globals.css`: buttons 36px and fields
  40px on a mouse/trackpad, 44px for both under touch (fields drop from 48).
  Small buttons are 32px on a mouse with a 44px minimum width and a vertical
  `::after` hit area to 44px; icon buttons are 36px with a 4px `::after` on every
  side. PRODUCT.md and MASTER section 8 are updated; the old 44px-everywhere rule
  is replaced, not silently broken.
- **4px control radius** for Button, Input, SelectTrigger, Textarea and
  Combobox. Panels stay 8px, dialogs 12px.
- **Right-aligned actions, primary last**, through a new `FormActions`
  primitive. Phones stack full width with the primary on top; `split` pins a
  wizard's Back or a status note to the start edge.
- **Scope:** primitives plus R3.8 surfaces. Other screens adopt `FormActions` in
  their own unit.

Pushback recorded with the choice: left-aligned primary actions under a single
form column are marginally faster to reach on long forms. Consistency with dialogs
and the owner's preference won; the rule is now one rule everywhere.

## Implementation

Guidance applied: Impeccable (context loader, detector), Emil design
engineering and Apple design. Motion is unchanged: no new animation, press scale
stays 0.97, no clinical-number animation.

- Primitives: `Button`, `Input`, `SelectTrigger`, `Textarea`, `Combobox` read
  the tokens. Thirty-one call sites that pinned `h-11`/`min-h-11`/`min-w-11`
  were cleaned, since those would have kept 44px on a mouse. Wrapping
  `h-auto` call sites keep the variant `min-height` floor. The Vitals
  module's action and select floors use the tokens; the distinct BP pair is
  unchanged.
- Encounter detail: a quiet back link (the R3.6 profile pattern) replaces the
  ghost Back action; an `h1` identity with patient code, stage tag and start
  time; Submit for Review and Mark Reviewed are full-size and right-aligned. The
  generic marketing description was removed. The review path is a four-segment
  ruled route; on phones it collapses to segments plus one line of text, with the
  full step words kept in the list for assistive technology. Sign-off keeps its
  warning band and deliberate Finalize. **Prescriptions moved below the clinical
  tabs**, so the tabs start in the first desktop viewport and prescribing follows
  the assessment. That is an order change only.
- New-visit wizard: the same header and route (it previously had no `h1`). The
  confirm step no longer repeats the name it is confirming; it says to check the
  name and code above. Confirm and Review use `FormActions` (Review is split:
  Back to Diabetes at the start, Submit at the end).
- `FormActions` replaces bare left-aligned saves in both interview forms, both
  legacy forms, Care Plan, Clinician Plan, Diabetes screening (split with its
  status note) and Prescription. Clinical Note's row was already
  status-left/actions-right and is unchanged.

Unchanged: labels, fields, units, validation, save refs, tab-save coordination,
role and flag gates, review/finalize semantics, locked records, offline and
outbox behaviour, Crisis dialog, BP signal.

## Validation

- Production build (audit flags), standalone TypeScript, changed-file ESLint and
  Prettier pass. Detector over the changed UI returns `[]`.
- Jest `--findRelatedTests` for the changed primitives and forms: **5 suites /
  11 tests** pass.
- Focused Chromium, first pass over 22 files: **139 passed / 29 failed**. Every
  encounter workflow spec passed (wizard, vitals, prescribing, clinical notes,
  diabetes screening). Failures were:
  - 26 pre-change size assertions measuring 44px under Desktop Chrome, which
    reports `pointer: fine` even at 390px. Fixed honestly: phone tests (portal,
    volunteer dashboard) now run in a `hasTouch` context, which reports
    `pointer: coarse`; icon/small targets are measured through
    `playwright/hit-target.js`, which includes the `::after` hit area; text
    buttons use the pointer-appropriate floor. No assertion was removed.
  - 2 real defects found and fixed: at 200% text and 320px the full-width
    header action could not wrap (13px overflow), and `sm`/`default` had lost
    their minimum width. A third, an all-sides `sm` hit area widening
    `scrollWidth` by 6px, was fixed by making the extension vertical-only with a
    44px minimum width.
  - `portal-shell` "held changes" (light and dark): the sync pill shows
    `failed`, not `held`. **Confirmed pre-existing:** the same test fails the
    same way on a baseline build with this unit's `apps/web` changes stashed.
    Not counted as a pass.
- Re-runs: 10 affected files **90 passed / 10 failed** (the `sm` scrollWidth
  case above), then after the final button change 5 files **37 / 37** passed
  (responsive components, data table, header, wizard, prescribing).
- Six-role normal-route audit: **12/12**, **228 rows, 0 axe violations, 0
  horizontal overflow, 0 errors**. This ran on the build before the final
  vertical-only `sm` change, which only narrows the hit area.

Not run: full e2e suite, flag-off build, Safari/Firefox, physical devices,
screen readers, installed PWA, virtual keyboard. Historical `#197` excluded.

## Follow-up: tabs and menu rows (owner request, 2026-11-10)

Tabs are 40px on a mouse (`--tab-height`), 44px by default and 48px under touch.
Select, dropdown and combobox rows are 36px on a mouse and 44px under touch
(`--menu-row-height`). Dropdown menu items previously had no floor (about 32px
on every device); under touch they now get 44px, which addresses the touch side
of the carried "short dropdown rows" finding. Verify it on a real device before
closing it.

Validation: build, TypeScript, lint and format pass. Twelve tab/row/target
files: **132 passed / 3 failed**. Two were the volunteer dashboard's 44px mouse
assertion, missed in the first sweep and now pointer-aware with the hit-target
helper. One was a dark-theme Vitals viewport check that passed on its
single-file re-run (the known local flake). Re-run of both files: **30/30**. The
six-role audit was not repeated for this follow-up.
