# R5.1 review: Patient portal

**Scope:** frontend-only patient portal on `ui-refresh/r1-1-tokens`: `/portal` (Overview),
`/portal/health` and `/portal/self-reports`, `/portal/appointments` (and request),
`/portal/self-reports/new`, and the "Your data" requests card. Local commit only; no push. No
separate agent review ran.

Guidance applied: the R4 contracts (counts in words, hairline phone lists, Accra dates, a waiting
decision leads), spec 7.11 (next appointment first, large actions on phones, plain language) and
Emil/Apple restraint on motion: the only motion added is a 150 ms chevron nudge on hover-capable
devices, off under reduced motion.

## What changed

- **Overview leads with the next appointment.** It was a row of four tiles (name, patient code,
  follow-up date, "Pending requests"), then readings, then the appointment. Now: one quiet line with
  the patient's name and patient code, then a "Next appointment" section whose confirmed visit sits
  in a ruled band (primary rule, larger time), then latest readings, then "From your care team",
  then reminders. Waiting requests are said at the end of the appointment description ("1 request
  is waiting for the clinic."); the follow-up date ends the care team description.
- **Quick actions are thumb rows.** Three full-width buttons became "What would you like to do?":
  hairline rows at least 64px tall, each with an icon, a title and a one-line hint ("Pick the days
  that suit you; the clinic confirms a time."). Link names start with the same titles as before.
- **Appointments.** The four count tiles (Upcoming confirmed, Requests pending, Completed visits,
  Cancelled or missed) are gone; the history descriptions now end with the counts in words. The
  rejected-request clinic note is a ruled band (2px destructive rule, faint tint) rather than a
  rounded box. The change dialog lost its `rounded-xl` override.
- **Health.** "Follow-up activity" was five boxed counts; it is now one sentence that names only the
  non-zero outcomes ("…: 2 requested, 1 completed."), or says there were none.
- **Dates.** `formatPortalDate` / `formatPortalDateTime` used the browser's zone; they now format in
  Africa/Accra, so every portal date is fixed at the root. Chart ticks were `11/12` (read as
  12 November or 11 December depending on the reader); they are `12 Nov` in Accra through a new
  `formatTrendLabel`, shared by the blood pressure, glucose, expanded-vitals and weight charts.
- **Forms.** Busy labels read "Sending request…" and "Saving reading…" (ellipsis character).
- **Your data.** The request history is hairline rows instead of a rounded bordered list, the status
  line is 14px instead of 12px, and Send request sits in `FormActions`.

Unchanged: every route, permission gate, claim and link-missing flow, write gate and offline copy,
held-changes behaviour, the R2.5 shell, and every e2e hook (headings, link names, `portal-write-gate`,
`stale-data-notice`, Request history, Submit appointment request).

## Not done in R5.1

- Account profile (`/account`) is shared with staff and was not restyled here.
- Request and log-reading forms keep their two-column summary layout and full-width submit (right on
  a phone, where the submit sits under the summary).

## Validation

- Production build with the CI clinical and PWA flags, standalone TypeScript, changed-file ESLint and
  Prettier pass.
- Jest `--findRelatedTests --maxWorkers=2`: **2 suites, 14 tests passed**.
- Focused Chromium, one worker: portal, portal-offline, portal-shell, appointments, settings:
  **55/55**. The first run failed 39 tests because the local database was missing every migration
  after 2026-10-31 (`/auth/whoami` returned 500 from `prisma.clinic.findMany`); `db:migrate:deploy`
  on the local Docker database, an API rebuild and a re-run fixed it. No code changed between runs.
- No string any e2e spec selects on was changed (grepped `e2e/` and `playwright/` for every old
  label).
- Six-role normal-route audit (guarded `nkwapa_audit` database, audit-flag build): **12/12, 228
  rows, 0 serious/critical or minor axe violations, 0 overflow, 0 errors**.
- Scratch evidence spec (a copy of the route-audit harness, deleted after the run): the patient's
  seven routes (six portal routes plus `/account`) at 390 and 320 in both themes: **7/7, 28 rows,
  0 violations, 0 overflow, 0 errors**, with a full-page screenshot per row in ignored
  `evidence/r5-1/after/`. It also listed every `main` link or button under 44px tall. The only hits
  were buttons at 36px, which is the `pointer: fine` size headless Chromium gets (44px on touch
  through `--button-height`, per R3.8), and the inline "privacy notice" link inside a sentence,
  which WCAG 2.5.8 exempts. The new quick action rows were not flagged (64px).
- Not checked: widths between 390 and 1440 for the portal beyond the six-role audit's 1440, real
  touch devices, Safari/Firefox and screen readers.
