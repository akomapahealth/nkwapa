# R7.7 review: Performance checks

**Scope:** frontend-only on `ui-refresh/r1-1-tokens`: performance across the workspace, portal and
public pages on the low-end phones and slow connections the clinics use, plus a custom 404 (owner
request in this session). Clinical saves, validation, permissions, flags, sync, Keycloak and the API
are unchanged. Local commit only; no push. No separate agent review ran.

Guidance applied: Impeccable (context, optimize; design hook and detector over the changed UI
files: no findings), accessibility (axe WCAG 2.2 AA on the new 404 in both themes), Emil Kowalski's
design engineering and Apple's design principles for the 404 drawing (purposeful motion on a rarely
seen page, ease-in-out for on-screen travel, ease-out reveal, transform and opacity only, a resting
frame that is the reduced-motion state).

## How it was measured

Turbopack prints no per-route sizes, so a scratch Playwright spec (deleted) loaded twelve routes in
a fresh context each (service worker blocked, cold cache) at **390 × 844**, with Chromium's CPU
slowed **4×** and the network at Lighthouse "slow 4G" (150 ms RTT, 1.6 Mb/s down). It recorded
transferred bytes by type from Resource Timing, time to the first `h1`, LCP, CLS with each shift's
sources and rectangles, and long tasks. A second pass timed the theme switch (four picks on
`/settings`) and a dialog (three open/close cycles of Create clinic) with the Event Timing API at 4×
CPU.

## Checked and left alone

- **Theme crossfade and dialogs do not delay input.** At 4× CPU: theme picks 104 ms for the first,
  then 40 to 48 ms; dialog open/close 64 to 160 ms; no long task during the theme switches. INP's
  "good" bound is 200 ms. The R7.6 `transition-colors` tween inside the crossfade stays (P3, not a
  cost).
- **Animations stay on transform and opacity** (MASTER 9.1 rule 10): the new 404 drawing included.
- **Recharts (≈139 KB gz)** appears in the byte counts of non-chart routes only because the sidebar
  and the 404's "Open dashboard" link prefetch `/dashboard`: the chunks start after the load event
  (219 ms vs 79 ms on `/patients`, unthrottled). Not render-blocking; it makes the dashboard open at
  once. Left as is.
- **Lottie** (`Hello.json` 310 KB, `checklist.json` 57 KB, `lottie-web`) loads only on the dashboard
  illustration, after a static rest frame paints, and never under reduced motion. Already lazy.
- **Workspace CLS 0.012** (all routes): the phone bottom bar and header controls settle once when
  the clinic bootstrap arrives. Below 0.1; not chased.
- **Unreferenced heavy files:** `public/images/nkwapa_logo-2.png` (816 KB) has no reference. It
  costs no page weight; kept as a brand source file. `nkwapa-favicon-logo.png` feeds
  `scripts/generate-pwa-icons.mjs`.

## Ranked findings left open

- **P2.** Shared critical JS is still about 456 KB gzipped (React DOM 72 KB, the Radix and Keycloak
  chunk 64 KB, the Next runtime 47 KB, and app code). Splitting the Keycloak adapter off public
  pages would be next, but it sits in the root providers; out of a frontend-only refresh.
- **P3.** `/dashboard` still has a 465 ms long task at 4× CPU on first render (role dashboards plus
  charts hydrating together).
- **Not checked:** real low-end Android hardware, real Safari, WebKit (cannot sign in against local
  http Keycloak), field data (no RUM in the app).
