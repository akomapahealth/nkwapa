## Cosign gate, before performance work

The first browser preflight created a volunteer draft at the review station but
stopped at a case-sensitive test label (`History` versus markup `history`, styled
with CSS capitalization). One selector correction uses anchored, case-insensitive
labels. This is harness evidence, not a product submission failure.

The corrected preflight submitted the volunteer note through the review-station
UI, with `PENDING_COSIGN` and no assigned doctor, then reached the doctor's
clinical-note view. The workflow cannot continue on the original build because
`ClinicalNotePanel.canCosign` requires `assignedDoctor.id === userId`. Station
notes intentionally have no assigned doctor and the API already authorizes any
clinic doctor. The UI therefore offers no cosign control. Product correction
`dbf6b14b` aligns the UI with that API rule and names the any-doctor submission
accurately. TypeScript, changed-file lint/format and 27 clinical-note API tests
pass. A later preflight reached and completed cosign, then exposed an ambiguous test
assertion (both badge and metadata say Cosigned). One correction asserts the
metadata term. The next preflight saved the HTN clinician plan, but Escape from
finalization failed to return focus to its invoker. Separate product commit
`8c8b836d` captures the invoker before the safe button autoFocus runs, then restores
it on confirmation close, falling back to main if the invoker disappeared or is
disabled. TypeScript, lint/format and the existing confirmation Jest case pass.

**Confirmed gate passed before performance measurement:** post-fix Chromium
preflight, one worker, no retries, one test **passed in 14.1 seconds** (17.9 seconds
including server startup). The volunteer writes and submits the real note in the
review-station browser UI; API readback requires PENDING_COSIGN and no assigned
doctor. The separate doctor browser cosigns it, enters the HTN plan, saves DM,
marks reviewed and finalizes. Readback requires FINALIZED, the original BP and HTN
classification, DM data and a care-plan follow-up date. Both cosign and finalization
dialogs exercise forward/backward tab trapping, Escape, focus return and keyboard
confirmation. Station setup and selected earlier station measurements/counselling
use the existing API fixture helpers. Auth state came from the earlier six real
browser sign-ins; this last preflight intentionally used --no-deps. Logs/traces
for every earlier attempt remain under /private/tmp/nkwapa-r88-r89/.

director, patient), staff patient list, doctor encounter and doctor patient record.

normal-motion illustration cost. Real Keycloak login sessions and the guarded
synthetic `nkwapa_audit` dataset are used. No performance score or field percentile

measurement attempt stopped after the inherited 10-second sync-readiness check

seconds without removing readiness checks. No app source changes were made for
performance.
