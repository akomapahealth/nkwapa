# R4.3 review: Director and system administrator oversight

**Scope:** frontend-only director and system administrator screens on `ui-refresh/r1-1-tokens`:
the director dashboard section (`DirectorDashboard`), `/metrics`, `/audit`,
`/reports/organization` (Report and Cohort analytics), `/admin/duplicates`, the network overview
(`SystemAdminDashboard`), `/admin/clinics` (and its metadata dialog), `/admin/users` (and its
access sheet), `/admin/duplicates/cross-clinic` and `/admin/data-requests`. Local commit only; no
push. No separate agent review ran.

Guidance applied: Impeccable (context loader, polish playbook, craft floor, detector), Emil design
engineering, Apple design. No motion was added: these are screens people return to many times a
day, and nothing here changes position on screen.

## What the code says about roles

- `/reports/organization` needs `ORGANIZATION.REPORT.READ`, which the seeded director does not
  hold; the director sees the shared no-access state there, as before. The system administrator
  ("staff" identity) is the one who reads it.
- `/admin/clinics` and `/admin/duplicates/cross-clinic` keep their second, system-admin (and, for
  clinics, director) gate inside `RouteGuard`. Unchanged.
- Merge, erasure, confirmation copy and every permission gate are unchanged.

## What changed

- **Warning ink narrowed to what cannot be undone here.** Deactivate account, Remove role and the
  clinic dialog's save when it takes a clinic offline were outlined warning buttons with
  `ShieldCheck`. Each is undone by Reactivate, Add role or reactivating the clinic, so they are now
  plain outline buttons and a routine Save, per the R4.1/R4.2 contract. The Deactivate section of
  the access sheet lost its red tint and red icon. Inactive and Deactivated badges are the neutral
  `secondary` badge instead of solid destructive red. Closing a deletion request and confirming a
  duplicate (which queues the pair for merge) keep the warning treatment.
- **Counts are said in words.** The boxed "Showing N" / "Loaded rows" tiles on clinics, staff,
  duplicates, cross-clinic and audit are gone; the section description ends with "Showing 10 of
  13." The audit log's three metric cells ("Visible events", "Has more results: Yes", "Audit
  scope: Clinic") were not figures; the events description now says "50 events loaded; older
  history is available below." Staff & Access dropped "Scope" (a clinic name in a metric cell) and
  "Account status 15 / 0" for Active accounts and Deactivated as separate counts.
- **Network overview.** The phone list of rounded boxes is gone: one `DataTable` at every width,
  the clinic column sticky while counts scroll sideways, counts right-aligned, "Encounters" now
  "Visits" like the KPI above it. The empty state is the shared `EmptyState` with Show all zones.
  Patients across clinics gained its icon. Director staff activity and both organization tables
  use the same sticky name and right-aligned counts.
- **Audit log.** The Rows select was blank: the table offered 25/50/100 but opened on 10. It opens
  on 25. Times are Africa/Accra with year and seconds (`formatOpsTimestamp`, new in `lib/ops.ts`);
  they were the browser's locale and zone. Filters sit in two rows of four instead of six plus an
  orphaned Request ID, and end in `FormActions` (Clear, then Apply filters, right-aligned). The
  8px button radius override is gone (controls are 4px). No-clinic uses `SelectClinicState`.
- **Data requests.** With no clinic chosen the page showed a skeleton forever; it now shows
  `SelectClinicState`. Received dates (and staff and portal invite dates, through
  `formatInviteDate`) read in Accra.
- **Duplicates.** Updated dates use `formatOpsDateTime` instead of a raw UTC `YYYY-MM-DD`. The
  cross-clinic callout, phone pager and the comparison sheet's decision and investigation blocks
  are ruled, not rounded boxes. Cross-clinic pair rows are hairlines that fill with `--selected`
  when chosen, with hover only on devices that hover.
- **Clinics and staff on phones.** Rows are hairline `article`s instead of rounded cards, and the
  roster's extra-access note is plain text, not a box inside a box. A filtered empty registry uses
  `EmptyState` ("Nothing needs attention" for that filter).
- **Access sheet.** Five `Card`s with boxed tiles inside (nested cards) became `RecordSection`s
  with `h3` titles; identity facts and role rows are hairlines. Created/Updated use Accra.
- **Metrics.** The failure-reason chart is one neutral series instead of a wall of red bars.

Unchanged: every permission and role gate, API call, merge/erasure flow, confirmation dialog and
its copy, e2e hook (region and table names, `duplicate-pair-card`, Show all zones, Needs
attention), and the station-flag Today board.

## Ranked findings

- **P2:** MASTER #274 still documents the older, broader warning rule (deactivate, remove role,
  take offline). The R4.3 paragraph beneath it narrows it; the next documentation pass should fold
  the two into one rule.
- **P2:** Page eyebrows ("Governance", "System administration", "Patient identity") remain on
  every page header. The craft floor bans eyebrows over headings, but `AppPageHeader`'s
  `eyebrow` is an app-wide pattern; removing it belongs to a single cross-app pass (R7), not one
  role's screens.
- **P3:** The audit table's Entity ID and Request ID columns are full UUIDs and run past 1440,
  so the last column scrolls. Shortening them would hide what investigators paste into search.
- **P3:** Organization tables keep a full outline "Open dashboard" button per row; a link would
  be quieter, but it is the row's only action and an e2e hook.
- **P3:** The light access-sheet screenshot caught the sheet mid-entrance (capture timing, not a
  defect); the dark one is settled.
- Carried forward: `portal-shell` held-changes baseline failure, open-overlay accessibility,
  transient sync, backend Crisis acknowledgement, Sunday appointment lifecycle, physical devices,
  Safari/Firefox, screen readers, no preceptor-only identity.
