# R2.5 review: patient portal shell

**Scope:** Frontend only, one unit on `ui-refresh/r1-1-tokens`. Local commit only;
no push. Implementation is complete; final verification results are recorded below.

## Implementation and authority

Confirmed: `SyncWithAuth` is the only production PortalLayout caller. Patient
portal, account and settings pages retain that shell and its existing bootstrap,
clinic, route guards and data providers. No API, database, authentication,
permission, queue, clinical copy or save behavior changed.

Below 600px, the portal reuses BottomNav and its draggable More Sheet with the
existing Overview, My Health and Appointments destinations. The R0 shorthand
Home/Health is not a reason to rename existing route labels. Top tabs replace the
phone bar from 600px. Health also marks self-report routes; Appointments marks
request routes. More marks account/settings. Layout selection uses CSS, preserving
mounted content and draft input.

The Header uses the compact brand mark and stacked, independently truncating
clinic/role context. Its former controlled left-menu trigger was dormant because
PortalLayout supplied no state. The explicit portal presentation removes that
trigger and assigns phone navigation to BottomNav. Existing clinic switching,
account, appearance, install and tour behavior remain. Existing authorized Header
utilities appear from 600px, avoiding an access gap at 600–767px when phone More
is hidden. Staff accounts visiting portal routes have explicit coverage. The card surface is inset
8px from 600px and stays on the approved canvas; phone main clearance includes
6rem plus the safe area. The portal does not newly mount staff chat.

More exposes profile/settings and the existing permission-filtered header/profile
utilities. It excludes staff sidebar destinations and empty navigation groups.
Sync recovery eligibility mirrors the existing sync pill: an active clinic plus
sync permissions, owned saved changes or held changes, including other clinics.
An empty patient queue without sync permissions exposes no recovery action.
Recovery opens the existing provider-controlled sheet after More releases its
focus trap. The originating More button or Header sync pill receives return
focus; crossing 600px falls back to main. Queue ownership and permissions stay
unchanged, including disabled sync actions for a patient without sync access.

The approved live artifact and its embedded frame, the checked-in pilot, R0
contracts, installed Next Link/usePathname documentation, Impeccable adaptation
and craft guidance, and installed shadcn composition guidance informed this unit.
No new dependency or component registry installation was needed. No separate agent
review ran. Only synthetic evidence was inspected, including R2.4's patient phone
baseline and the new portal phone, wide, dark, enlarged-text and More images.
