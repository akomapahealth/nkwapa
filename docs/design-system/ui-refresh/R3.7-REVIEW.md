## Implementation and authority

Confirmed: the R3.7 handoff, R3.6 review, MASTER/PROGRESS, R0 sections 4–6 and
8–9, checked-in pilot, live artifact's embedded Blood pressure screen, installed
Next client/CSS docs and actual Vitals consumers informed this unit. Emil design

shadcn Radix Button/Input/Select docs were retrieved through the CLI and read.
No dependency, preset, font or token upgrade was made. The initial sandbox CLI
request failed DNS resolution; the escalated documentation request succeeded.
Only synthetic data and the separately guarded audit database were used. The
real-patient and third-party reference directories were never inspected. API
logs were redirected and database credentials were not printed.

The boundary is the existing patient-chart Vitals history/trends and the shared
`VitalsForm`, used by encounter Vitals, the new-encounter wizard, blood-pressure
station and anthropometry station. The form uses the existing ruled RecordSection
foundation in place of nested bordered panels. Small unfilled icons support
section headings; a distinct systolic/diastolic pair makes the reading easier to
scan without changing labels, units or input behavior. Ordinary fields use one
column, two from 30rem available width and three from 48rem. History measurements
use up to four columns; read-only groups use up to two. These are CSS changes to
one mounted tree, not alternate forms or data models.

Selected values, notes and actions can wrap at enlarged text. The save/review row
is sticky within the form on phones and uses observed navigation, chat-launcher
and action-row geometry for clearance. At narrow text widths, chat clearance is
reserved vertically below full-width actions so the labels remain readable.
The row stays in its form's bounds; subsequent station handoff controls retain
their existing flow. No fixed duplicate save control or new focus stop is added.
Fields receive matching scroll clearance. No entrance, repeated selection or
clinical-number animation was added.

`FieldError` appends `-error` to its field id. Existing Select, temperature, Other
context and Notes calls were passing an already-suffixed id, creating broken
descriptions. They now reference the actual messages, and Other context controls
use the same error-association helper as numeric fields. Existing error text,
validation rules, first-invalid logic and field values remain. Select items use
the existing Radix SelectGroup; the shared primitives stay unchanged.

Chart history retains record identities, reverse chronology, source-visit links,
author/clinic/time provenance, encounter and locked badges, cursor pagination,
empty/loading/error/retry/offline states and units. Trends retains its requests,
time range, selected measurement, exact values, provenance descriptions and
literal table alternatives. Quiet selected surfaces and a smaller value role
replace the oversized measurement selector figures. An explicit zero-minimum
one-column grid prevents the blood-pressure chart from widening the page at
200% root text. ChartFrame receives only an inert `data-chart-frame` marker;
Vitals-local CSS wraps its heading/action row. Other chart consumers keep their
existing layout.

Two small adjacent wrapping corrections were required for the enlarged encounter
viewport: the prescription-allergy acknowledgement label can shrink/break long
words, and the encounter container permits long-word wrapping. No prescribing
fields, acknowledgement rules, permissions or handlers changed. R3.8 still owns
the encounter redesign.

Confirmed by diff: no backend, API contract, auth/RBAC definition, schema,
clinical threshold/classification, units/preferences, defaults, validation range,
consent, chronological fetch, cursor model, offline/outbox/replay, save or
finalize handler changed. The Crisis reading is still saved before the existing
one-button alert is awaited. Recording acknowledgement remains the separate
backend task in `TASK-crisis-acknowledgement.md`.

## Candidate failures and diagnostics

The first invocation completed **59 passed / 3 failed / 9 not run**, including
six authentication setups, and reported one additional runner-level error after
the early stop. The two new edit-form cases exposed enlarged-text overflow.
The Crisis fixture omitted the required measurement site, so the validator
correctly refused to save; the fixture was corrected. This was not a failure
of Crisis classification or acknowledgement. All station Crisis/error checks
in that invocation passed. No failed or not-run case is counted as a pass.

A separate enlarged-encounter geometry diagnostic passed **1/1** and located the
allergy-label overflow. This is an investigation, not regression coverage.
The second seven-case invocation completed **2 passed / 3 failed / 2 not run**,
with one additional runner-level error after the early stop. It passed the
light edit-form and corrected encounter Crisis checks, but exposed remaining
enlarged encounter/loaded-chart overflow. Long-word wrapping and waiting for
measured chart layout addressed part of that finding.

The third invocation completed **5 passed / 2 failed**. Edit-form light/dark,
Crisis, error associations and read-only measurements passed; both loaded-chart
cases retained 31px overflow at 200% root text. A one-case chart geometry run
then failed and identified the implicit grid track growing to 319px and the
chart header's minimum content. The final explicit grid/header correction
addresses that source defect. The larger transient width seen during an earlier
resize is kept distinct from the persistent 31px finding. The final verification
waits for measured layout; it does not reduce the zero-overflow assertion.

Visual inspection also found that reserving chat clearance horizontally could
split the enlarged Save label into short fragments. The final narrow-container
rule reserves the launcher's measured height below full-width actions instead.
Successful production builds ran once per UI source state; spec-only changes did
not trigger builds. Candidate logs, screenshots and geometry output are retained
separately from the final evidence.
