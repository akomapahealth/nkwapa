# R1.6 DataTable review

R1.6 refines the shared table presentation and adapts the existing card slot to
available container width. Frontend only. The approved pilot's table surfaces and
R0-AUDIT section 4 are the visual authority. No table library or fetching contract
changed.

## Shared contract and scope

- `DataTable` uses `bg-card`, `bg-surface-2` sticky headers and hover/focus-within
  rows, with quiet `border-border` dividers instead of the strong top rule.
- `renderMobileRow` remains the sole card API. Below 60rem of container width,
  cards show with shared sorting controls; at or above it, the table shows.
  This threshold accommodates patient identification/contact columns and two
  record actions, rather than adopting the pilot's reduced 600px table literally.
- The one TanStack instance supplies both layouts. Filtering, sorting, pagination,
  row IDs and action callbacks are shared. CSS does not request data or reset
  state. Inactive controls are removed from the accessibility tree by display.
- The same refresh indicator covers both presentations without taking layout
  space. Both presentations use the supplied empty state or the same fallback.
- Tables without a card renderer continue to scroll in a named keyboard region.
  Browsers without container queries retain the complete table. Existing viewport
  `hideOnMobile` metadata is unchanged.
- Patient registry and StaffInvitesCard are the two production card consumers;
  their existing action implementations and caller-owned filters are retained.
  The other 17 production consumers retain their tables or independent responsive
  layouts. Import inventory matches HANDOFF-R1.6.

## Verification

The new `data-table-surfaces.spec.js` uses the existing fixture bundle helper and
synthetic records, without a public specimen route. It exercises client and
controlled-server modes, row/action identity, sorting and reset, filtering,
pagination, responsive visibility, request-callback stability across resizing,
empty states, non-shifting refresh, keyboard scrolling, sticky headers, numeric
alignment and coarse-pointer cells. Theme/width scans run axe without exclusions.
Widths: 390, 744, 1024 and 1440px, plus 991/992px viewport widths to put the
fixture's 16px gutters on both sides of the 960px content threshold.

The first new-spec attempt failed on two assertion assumptions: accessible name
whitespace, and expecting `animation-name: none` instead of the existing reduced
motion duration/iteration clamp. Assertions were corrected to test the actual
accessible name and motion contract; no product validation was removed.

The sandboxed Turbopack build stalled at compilation and was interrupted. The
approved build outside the sandbox completed. Final check totals and evidence
are recorded in PROGRESS.md.

Actual-consumer supplement: patient registry and staff invitations, both themes,
at 390/744/1024/1440px, followed by a 560px panel in a 1440px viewport and a sort.
All 16 closed-state component axe scans and all 20 bounds checks passed before
opening Rows per page. The four open Select full-page scans failed, each with
`aria-hidden-focus` (serious), `page-has-heading-one` and `region` (moderate).
Per-case JSON and screenshots are retained in the ignored evidence directory.
The temporary spec used the real authenticated routes, set only the theme,
sidebar and a local 560px presentation width, and performed sorting and Select
opening. It was removed after capture; a local copy is beside the diagnostics.
No axe exclusion or expected-failure annotation was added. A repeated capture
corrected the first capture's per-worker JSON overwrite so all four case results
remain available.

Final normal-route audit: six roles, 228 route/theme/width rows, zero errors,
zero serious/critical or minor axe findings, and zero horizontal overflow.
Harness tests: 12/12 pass. This does not clear the four open-Select failures.
The ignored `evidence/r1-6/` directory contains `route-audit.json`,
`validation-summary.json`, per-case Select JSON, filtered logs and 168 after
screenshots (114 routes, 30 shared component/table, 24 actual consumers).
