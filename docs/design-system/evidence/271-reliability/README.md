PR #295 merged into `release/dev` at `433586a8e1c394b00a88ff877de1263a3c079750`. This follow-up covers the failures recorded in `evidence/271/README.md` and no #272 work. All browser data is synthetic local E2E data. No database reset, reseed, or production action was used.

## Portal contrast

The same `/portal/self-reports/new` route was captured before and after the scoped text-color change, with the station-workflow flags ON for both API and web. `before/` and `after/` contain 1440px full-page and 390px first-screen JPEGs in light and dark themes. The selected blood-pressure description is the only intentional visual change. The captures were visually reviewed.

`axe-before.json` and `axe-after.json` each contain four light/dark, desktop/phone scans with zero serious or critical findings. A separate normal-motion first-render WCAG scan reproduced the intermittent finding in one of 12 before visits. The selected description was `#657177` on `#e4efed`, 4.27:1, below 4.5:1 for 14px text. `contrast-after.json` has zero findings in 12 visits. The retained portal spec also scans all three choices in both themes while switching selection. These runs support the targeted fix; they do not prove every timing and device combination.

The first complete OFF-build suite exposed a separate `/portal/appointments` contrast finding on three "Clinic note" labels. The saved `appointments-contrast-before.json` reproduces three failing nodes at 4.27:1 on their light tinted surface, and `clinic-note-before.png` shows the text. The label now uses the existing `destructive-ink` token. The same capture after rebuilding has zero findings in `appointments-contrast-after.json`, with its appearance in `clinic-note-after.png`. A new E2E case creates a genuine rejected request and checks the note in both themes, so a fresh CI database exercises this state.

## Test failures investigated

- The four `#197` offline-copy cases failed on the unchanged `release/dev` build when the test left `/stations` as soon as its heading appeared. That aborted an in-flight board/shifts read before the IndexedDB workspace row was saved. A browser diagnostic showed both API reads returned HTTP 200 and the distinct cache entries were persisted when given time. The spec now waits for the entry whose survival it asserts before navigating. The real cache, outbox, held states, and app behavior were not changed.
- Claim cases consumed one seeded invitation, and the PWA claimant case later observed the claimed account. Each now uses a fresh real invitation and Keycloak account created through the local app, with no authentication mock. The seven claim assertions and exact PWA claimant destination remain.
- Two triage cases consumed seeded appointment requests. They now create distinct requests through the real patient endpoint, scope the UI row to their own reason, and verify the saved confirmation. The cancelled-decline case rejects its own synthetic request after the assertion.
- Clinic creation persisted, but a later page held the new clinic after earlier runs expanded the registry. The test reloads and pages to the exact saved code.
- Two API rate-limit unit cases inherited the E2E job's high-volume overrides. The spec clears those variables in its own fixture and restores the environment afterward. Production limits and assertions are unchanged.
- Later complete-run failures came from accumulated synthetic records. The chat picker contained nine volunteers sharing one display name, so the socket round-trip test now chooses the first matching directory entry. The volunteer directory had over 25 rows; the roster test reloads and pages to each exact saved volunteer before proceeding with its duplicate, roster and email assertions.
- The second and third complete runs each exposed one PWA setup failure: Chromium reported that the promise returned by the test helper's IndexedDB write was garbage collected. Retaining and closing the connection alone did not fix it. The fourth run, with a synchronous write and observable error state, exposed the underlying condition: `NkwapaDb` had been opened before Dexie created the `outbox` store. The helper now waits for the app's schema version 14 or newer before opening the database, retains the request and transaction, and polls for completion from Node. The existing queued-count and offline-launch assertions remain. The PWA and responsive files passed 38/38 together after this correction.
- The fourth run also observed a 768px dashboard overflow of 264px immediately after a viewport resize. An isolated 20-repeat run reproduced two transient readings (264px at tablet and 953px at phone). The responsive spec now polls the unchanged `<=1px` bound for up to five seconds after each resize, so a persistent overflow still fails. The same 20-repeat run then passed 20/20.
- The fifth complete run passed the PWA case at its usual position. Eight other-clinic keyboard cases failed because the discard control was temporarily disabled during sync; focusing it left focus on the sheet trigger, and Enter closed the sheet. They now wait for the button to become enabled and use that button's `press('Enter')`, retaining the confirmation assertion. A portal axe scan caught the 150ms workspace opacity entrance on `/portal/health`; partially transparent text measured below 4.5:1 while the page was fading in. The sweep now waits for `.animate-page-in` to reach opacity 1 before scanning, with normal motion and the zero-violation assertion intact. These two files passed 29/29 together after the timing changes. The brief entrance contrast remains a known presentation limitation for the later motion issue.
- The sixth complete run passed outbox, portal, PWA, responsive, chat and roster. One merge-preview case failed after searching for a combined first-and-last-name string. The trace shows the registry returned HTTP 200 with zero items. Its search matches one field at a time, so the test now searches the freshly created duplicate by its unique chart code. All 12 merge-preview cases passed against the accumulated database afterward.
- The seventh complete run passed merge preview but had one offline prescription replay failure. Its trace showed the offline POST failing as expected, then no `/sync/push` and an empty prescription list. The test had switched online and checked for queue drain before the form finished the IndexedDB write. It now waits for the app's "saved on this device and pending sync" notice, which is set after the outbox write, before reconnecting. The 13 prescribing cases passed together after this change.

The final complete station-workflow-OFF run passed **387 tests, 48 skipped, zero failed** in 12.9 minutes, including claim, triage, clinic pagination, portal contrast, PWA, outbox, merge preview, prescribing, chat and roster. The final station-enabled run passed **27/27**, including all four `#197` cases, with both API and web flags ON. An earlier broader ON run passed 92/92. The CI-env API Jest run passed 2,842 tests with 62 skipped; web Jest passed 933/933 and db Jest passed 837 with 54 skipped. Security scan, workspace lint, Prisma generate, typecheck, chart and token checks, 20 script tests, whole-repo Prettier, and DB/API/web builds passed.

Earlier complete OFF runs were used to investigate failures without deleting fixtures or relaxing assertions. They progressed from 382 passed/3 failed through 386 passed/1 failed as each new accumulated-data or timing condition surfaced; the seventh had 386 passed/1 failed. Their logs and traces are in local scratch, not committed. No database reset was used.

## Reproduce

Use the CI E2E environment from `.github/workflows/ci.yml` merged over the local environment without printing secrets. Build with both station-workflow flags ON for `station-workflow.spec.js` and this capture config. Set absolute `WEB_DIR` and `EVIDENCE_DIR`, then run the `capture` project in `playwright.config.cjs` with one worker. Rebuild with both flags OFF before running the default full E2E suite. Keep builds separate from active Playwright runs.
