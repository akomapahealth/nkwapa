# Nkwapa 2.0 release notes

**Status: approved by the owner, 2026-11-04.** Release `release/dev` into `main`, after v1.5.1
(2026-11-01). It is the Nkwapa 2.0 redesign, epic
[#229](https://github.com/akomapahealth/nkwapa/issues/229): 25 pull requests, #284 to #309 (there
is no #307, which is an open issue). Nothing else is in `release/dev` that is not in `main`.

The version comes from the release label on the `release/dev` into `main` pull request. A redesign
of every screen suggests `release:major` (2.0.0); the owner decides.

The next section, from its heading to "For the team", goes into the release pull request's
description as it stands. The Tag Release job copies it into the GitHub release, and the home
page's What's New dialog reads it from there (`apps/web/lib/release-notes.ts`).

## For clinic teams

### New

- **A new look across Nkwapa.** Every staff page, the patient portal, the sign-in pages and the home page now share one calm layout: clear headings, numbers first, and teal only on what you can press. What you record, and how it is saved, has not changed.
- **"Needs you now" at the top of every dashboard.** Volunteers, doctors, managers, directors and admins each see the work waiting for them first, with one button for each item, before today's counts and trends.
- **See how long patients have waited.** On the Today board and the manager dashboard each station is a lane, and each patient's bar grows with the minutes they have waited. Waits over 20 minutes are marked in words as well as colour, and a station with nobody on it says so.
- **A table under every chart.** Every dashboard and report chart has a table switch, so you can read the exact numbers instead of estimating them from a line.
- **A week view for appointments.** Appointments open on a seven-day strip; choose a day to see its visits. Times are shown in Ghana time and the page says so.
- **A side menu you can fold away.** Fold the side menu down to icons for more room, with its button or the `[` key. Point at or tab to an icon to see its name.

### Improved

- **Message delivery and Clinic settings have moved.** Message delivery (formerly Notifications) is the send icon at the top of the page, and Clinic settings is in your account menu. The pages and who can open them are the same.
- **Setting up an account is one clear journey.** From the invitation email to the first sign-in, each screen says which step you are on, and an expired or already-used link explains what happened and what to do next.
- **The patient portal works better on phones.** Three main buttons along the bottom, one "Request an appointment" button, and your readings as a table as well as a chart.
- **Clearer queues and sign-off.** Each queue shows its count once, a visit's stage is written in words, and Finalize, Sign note and Cosign note look different from Save.
- **Corrections stay visible.** A cancelled station stop or appointment time is crossed out, with who changed it and when, instead of disappearing.
- **Honest screens when the connection drops.** A list that could not load says so instead of looking empty, a saved copy is marked as possibly out of date, and changes waiting to sync stay on screen. The top of the page says "Review saved changes" while anything is waiting.
- **Easier to use on phones and tablets.** Buttons and links are bigger, wide tables scroll inside their own box, and side panels stay clear of the phone's notch.
- **Forms show their problems first.** When a form cannot be saved, a list of what to fix appears at the top, and screen readers announce error messages straight away.
- **A shorter, calmer home page.** Fewer words, real Akomapa photographs, and a What's New list that stays readable as releases grow.
- **Faster, steadier text.** Nkwapa's fonts now load from Nkwapa itself instead of an outside service.

### Fixed

- **The Sex field at patient registration** now has a proper label, so screen readers name it.
- **Hard-to-read text** in the patient portal and on the home page now has enough contrast.

### What did not change

Checked with `git diff origin/main origin/release/dev`:

- **No database migration.** `packages/db/prisma/migrations` is unchanged.
- **No API change.** The only file changed under `apps/api` is a test
  (`rate-limit.guard.spec.ts`). Permissions, route guards, feature flags, consent, clinical
  fields and save behaviour are unchanged.
- **No new environment variable** in any `.env.example` or `deploy/env/` template.

### What to know before deploying

- **The Keycloak login theme changed** (#277): new templates, styles and message keys under
  `infra/nkwapa/keycloak/themes/nkwapa/`. It ships with the auth service deploy, which
  `deploy.yml` runs alongside web and API. Check the sign-in, reset-password and expired-link pages
  on staging first.
- **Two web dependencies were added:** `@radix-ui/react-tooltip` (collapsed side menu) and
  `lenis` 1.3.27 (smooth scrolling on the home page, wide screens only).
- **Fonts are self-hosted** through `next/font` (#287); no request goes to an outside font host.
- **The seed knows two more test identities** (#285), `SEED_E2E_MANAGER_SUB` and
  `SEED_E2E_DIRECTOR_SUB`. They do nothing unless set. Never set them in production: the
  post-deploy gate fails if active seed fixtures are found there.
- **CI has one more check:** `npm run design:check-tokens` measures colour contrast for the
  semantic tokens in both themes.

## Rollback

Every change in this release is presentation, documentation or tests, with no migration and no new
configuration, so rolling back is a revert.

1. **Whole release.** On `main`, revert the merge commit of the `release/dev` into `main` pull
   request (`git revert -m 1 <merge sha>`) in a pull request labelled `release:patch`. Merging it
   redeploys web, API and auth through `deploy.yml`, and the post-deploy gate checks the result as
   usual.
2. **Database.** Nothing to do. No schema or data change ships in this release.
3. **Login theme.** Reverts with the auth service deploy in step 1. A browser that has the new
   theme cached gets the old one on its next page load.
4. **Installed app (PWA).** Installed copies pick up the reverted build the next time they load.
   If one stays on the new version, follow "Service Worker And Installed App (#206)" in
   [04_OFFLINE_FIRST_AND_SYNC.md](../specs/04_OFFLINE_FIRST_AND_SYNC.md). Held offline changes are
   kept: the outbox format did not change in this release.
5. **One area only.** Each pull request above is self-contained and can be reverted on its own.
   The foundations (#287, #288, #289, #290) sit under everything after them, so revert later
   areas first and the foundations last.
6. **What's New.** The home page reads the latest GitHub release. After a rollback release, its
   notes should say plainly that the new look was withdrawn.

# Nkwapa 2.0.1 release notes

A patch release, `release:patch`, after v2.0.0 (2026-11-05). It ships the redesign follow-ups and
background notifications: #312, #319, #320, #321, #322 and #323.

The release pull request's "For clinic teams" section lists the items below as "New in 2.0.1",
"Improved in 2.0.1" and "Fixed in 2.0.1", then every 2.0 item above as "New in 2.0", "Improved in
2.0" and "Fixed in 2.0". What's New shows only the latest release, so carrying the 2.0 notes keeps
them on the home page. `FALLBACK_RELEASE` in `apps/web/lib/release-notes.ts` holds the same list.

## For clinic teams in 2.0.1

### New

- **Notifications while Nkwapa is closed.** Turn on notifications in Profile on each device. Staff hear about new messages, patients assigned to them and notes waiting for their cosign, and patients hear when the clinic answers an appointment request. A notification never shows patient details. Signing out turns them off on that device, so the next person chooses for themselves. If you had notifications on before this release, sign in again so the device is set up.
- **Log in from the home page.** The home page has a Log in button for invited accounts. The sign-in page asks whether you are a patient or clinic staff, and shows the help that fits you.
- **Measurements in your clinic's units.** Glucose, weight, height and HbA1c are now entered and shown in your clinic's units. Ghana clinics see glucose in mmol/L (7.0 mmol/L is the same as 126 mg/dL). If a meter reads mg/dL, use the unit switch beside the glucose box. A director can change the clinic's units in clinic settings.

### Improved

- **Cancelled appointments say who, when and why.** A cancelled visit on the schedule is still crossed out. Underneath, it now says who cancelled it, when, and the reason they gave.
- **Queue tabs show the real count.** A lane holding more than 50 visits shows its full number, and "Show more" loads the rest.
- **Appointment times are in clinic time.** Reschedule and confirm forms read and fill times in the clinic's time zone, whatever time zone your device is set to.
- **Ask for a new invitation.** If your invitation link has expired, the "No invitation found" page has an "Ask for a new invitation" button. The clinic sees your request on the invitation and can send you a new one.
- **Tidy up the staff invitations list.** Expired and cancelled invitations now have a Remove button. It takes them off the list without deleting the record, and you have a few seconds to undo. You can also filter the list by Open, Expired, Accepted or Cancelled.
- **The dashboard remembers your tab.** It opens on the tab you used last, for each clinic.
- **Clinic settings has its own icon.** It shows sliders in the account menu, so it no longer looks like Your settings.

### Fixed

- **Clearer pages for screen readers.** Headings and lists on Stations, Settings, the organization report, Data requests, Volunteers and the patient record are now in the right order, so screen readers announce them properly.

## For the team in 2.0.1

### What changed

- #312: idempotency keys for online writes, appointment cancellation details, the full queue
  counts, clinic-time appointment forms and invitation renewal requests (#307).
- #319: directors remove expired and cancelled staff invitations.
- #320: self-hosted font files, the remembered dashboard tab, the Clinic settings icon and the
  route-audit heading fixes (#313, #315, #316, #318).
- #321: measurements in each clinic's units.
- #322: invite-only Log in on the home page header, and the patient or staff choice on sign-in.
- #323: background Web Push (#250), and the #313 route audit re-run with two more fixes.

### What to know before deploying

- **Six migrations**, each additive and safe to re-run on its own: `IdempotencyRecord`,
  appointment cancellation columns, invitation renewal columns, clinic measurement units (with a
  backfill from each clinic's country), staff invitation removal, and `PushSubscription`.
- **New, optional environment variables** for background notifications:
  `WEB_PUSH_VAPID_PUBLIC_KEY`, `WEB_PUSH_VAPID_PRIVATE_KEY` and `WEB_PUSH_SUBJECT` on the API
  (Render), and `NEXT_PUBLIC_WEB_PUSH_VAPID_PUBLIC_KEY` on the web build (Vercel). Generate one
  pair per environment with `npx web-push generate-vapid-keys`, and redeploy the web app after
  setting the public key. Until the keys are set, push stays off and notifications still work
  while Nkwapa is open.

## Rollback in 2.0.1

1. **Whole release.** Revert the merge commit on `main` in a pull request labelled
   `release:patch`, as for 2.0.
2. **Database.** The migrations only add tables and columns, so the reverted code runs on the
   newer schema. Leave them in place.
3. **Background notifications only.** Unset the two `WEB_PUSH_VAPID_*` keys on the API and
   restart it. Nothing is sent after that, and notifications in an open app keep working.
