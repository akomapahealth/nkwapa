# Nkwapa 2.1 release notes

A minor release, `release:minor`, after v2.0.1 (2026-11-06). It ships the Layered Clinical
Workspace refresh, the review-station cosign fix, clinical note previews and screening overwrite
notices: #326.

The release pull request's "For clinic teams" section lists the items below as "New in 2.1" and
"Improved in 2.1", then every 2.0.1 and 2.0 item under its own heading. What's New shows only the
latest release, so carrying the older notes keeps them on the home page. `FALLBACK_RELEASE` in
`apps/web/lib/release-notes.ts` holds the same list.

## For clinic teams

### New

- **A refreshed workspace for every role.** Volunteers, doctors, managers, directors and patients each open on their own work first. The menu fits the screen: a side menu on a computer, a slim rail on a tablet and a bar along the bottom on a phone, with the rest under More.
- **Review-station notes without choosing a doctor.** A volunteer at the review station can submit a note without picking a doctor first. Any doctor at the clinic can cosign it. A note assigned to a named doctor still stays with that doctor.
- **A notice when your screening save is replaced.** If a colleague's offline save replaces blood pressure, diabetes or vitals answers you saved more recently, you get a notice in Notifications that opens the visit. Their save still goes through, so nobody is blocked.
- **A preview on each clinical note.** The notes list in a patient record shows the first lines of each note, so you can find the right one without opening them all.

### Improved

- **Clearer screening and clinical forms.** The blood pressure and diabetes interviews and the clinical forms show which section you are in and whether your answers are saved.
- **Signing asks you to confirm.** Signing a note and finalizing a visit ask once before they happen.
- **The patient portal fits phones better.** The header and bottom bar adjust to the screen, and long appointment titles wrap instead of being cut off when text is enlarged.
- **Saved changes say what they are waiting for.** The sync list separates changes that are waiting, changes that need your attention and changes you can retry.
- **Settings on one page.** Your settings sit in one readable column, with links to notifications, installing the app and your clinic's details.

## For the team

### What changed

- #326: shared tokens, controls and adaptive shells; one home per main role; the refreshed
  clinical workspaces, patient records, portal, sign-in, admin and public screens. Role-by-role
  detail is in `docs/design-system/ui-refresh/RELEASE-NOTES.md`.
- A review-station volunteer's note no longer needs a manager-assigned doctor. The API already
  let clinic doctors cosign it; the screen now shows the action for unassigned pending notes.
- `GET /clinics/:clinicId/patients/:patientId/clinical-notes` adds `preview` to each summary.
  Existing role, patient-scope and row-level checks apply, and previews are not cached offline.
- Blood pressure, diabetes and vitals sync payloads accept an optional `baseUpdatedAt`. A stale
  save still applies. When it replaces another clinician's newer save it is audited as
  `CONFLICT_OVERWRITTEN` and that clinician gets an inbox notice. A client talking to an older API
  retries once without the field.
- Accounts without sync permission, such as patients in the portal, no longer start automatic
  sync passes.
- CI runs the E2E suite as four shards plus a station-workflow job, and stops a run at 25 minutes
  or 40 failures.

### What did not change

- Clinical permissions, signed-note immutability, offline queue identity and save validation.
- Volunteers still add plans, classifications and prescriptions where they could before.
- There is no blocking conflict dialog on screening saves.

### What to know before deploying

- **Two migrations**, deployed unchanged and in order. `20261113090000_inbox_notifications` adds
  the `InboxNotification` table with its indexes, row-level security and privileges.
  `20261113190000_station_note_cosign_guard` replaces the `ClinicalNote_state_check` constraint
  and adds a submission guard trigger. Both are written to be re-run safely.
- **No new environment variables.**
- **The staging Keycloak memory settings** in `docs/OPERATIONS.md` are a proposal. They have not
  been deployed or measured, and production is unchanged.
- **The visual comparison gate is open.** The last audit run compared 50 screens against
  baselines captured from a live database and clock: 24 passed and 26 failed. Those baselines
  have been removed. Measured results and open checks are in
  `docs/design-system/ui-refresh/R8.8-R8.9-REVIEW.md`.

## Rollback

1. **Whole release.** Revert the merge commit on `main` in a pull request labelled
   `release:minor`.
2. **Database.** Leave both migrations in place. `InboxNotification` is a new table the older
   code does not read. The replaced note constraint is looser than the old one, so notes the
   older code writes still pass it. Notes a review-station volunteer submitted without an
   assigned doctor stay in the database after a revert, and the older screen does not show their
   cosign action.
